# PRD · AISC Study Hub

작성: 관리자 · 상태: 확정(실습용)

## 1. 문제

소학회 스터디는 매주 열리지만 일정은 단톡방 공지에, 출석은 각자 기억에 흩어져 있습니다. “지난주에 뭐 했지?”, “누가 몇 번 나왔지?”를 확인하려면 대화를 거슬러 올라가야 합니다.

## 2. 목표

- 스터디 일정을 한곳에 등록하고 찾아본다.
- 일정마다 누가 출석했는지 체크하고, 멤버별 출석률을 바로 본다.
- (실습 목표) 팀원 4명이 두 명씩 짝을 지어 짝마다 기능 두 개를 맡고, **PR·리뷰·머지로 하나의 앱을 완성**한다.

## 3. 사용자

소학회 운영진(일정 등록·출석 체크)과 스터디원(일정 확인). 이번 버전은 한 브라우저에서 운영진 한 명이 관리하는 상황을 가정합니다.

## 4. 범위

| 구분 | 내용 |
| --- | --- |
| 이번에 구현 | 일정 등록(#2), 일정 목록·검색(#3), 출석 체크·출석률(#4), 스터디 요약 카드(#5) |
| 관리자가 미리 제공 | 데이터 타입, localStorage 저장, 멤버 명단, 예시 데이터 버튼, 화면 뼈대 |
| 이번에 하지 않음 | 로그인, 여러 기기 동기화, 서버·DB, 일정 수정·삭제(OQ-01), 알림 |

## 5. 기능과 수용 조건(AC)

### #2 일정 등록 — 짝 1
- **AC-01** 제목이 비어 있거나 공백뿐이면 등록되지 않고 `일정 제목을 입력하세요.`가 보인다. 날짜가 비어 있으면 `날짜를 선택하세요.`가 보인다.
- **AC-02** 제목·날짜(주제는 선택)를 넣고 등록하면 “등록된 일정” 개수가 1 늘고, 입력칸이 비워지고, 새로고침해도 남아 있다.

### #3 일정 목록·검색 — 짝 1
- **AC-03** 검색어를 넣으면 제목이나 주제에 그 글자가 들어간 일정만 보인다(대소문자·앞뒤 공백 무시). 결과가 없으면 `검색 결과가 없습니다.`가 보인다.
- **AC-04** 일정은 날짜가 늦은 것이 위에 오고, 각 항목에 날짜·제목·주제·출석 인원(`출석 2/4`)이 보인다.

### #4 출석 체크·통계 — 짝 2
- **AC-05** 일정을 고르고 멤버를 체크·해제하면 바로 저장되고, 일정 목록의 출석 인원도 함께 바뀐다.
- **AC-06** 멤버별 출석 횟수와 출석률(%, 반올림 정수)이 표로 보인다. 일정이 하나도 없으면 `아직 일정이 없습니다.`가 보인다.

### #5 스터디 요약 카드 — 짝 2
- **AC-07** 화면 맨 위에 카드 세 개가 보인다: 전체 일정 수, 일정당 평균 출석 인원(소수 첫째 자리, 예 `1.7명`), 가장 최근 일정(날짜가 가장 늦은 일정의 날짜·제목).
- **AC-08** 일정이 없으면 `0개` · `0.0명` · `—`로 보이고, 일정을 등록하거나 출석을 체크하면 카드 값이 바로 바뀐다.

## 6. 성공 기준

- PR 4개가 모두 CI 통과·리뷰 승인 후 main에 머지된다.
- 최종 main에서 `npm run dev`로 실행해 [통합 확인표](#7-통합-확인표)를 모두 통과한다.
